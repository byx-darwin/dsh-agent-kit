# doctor、setup 与设置页

三种方式读写的是同一份配置：Profile 目录下 `cordis.patch.yml` 中 id 为 `agent-kit-*` 的几行。手动编辑这个文件，效果也完全一样。

## doctor：检查

<CopyCommand command="npx @mc/dsh-agent-kit doctor --profile my-agent" />

- 只读，不修改任何文件，也不需要启动 dsh。
- 只检查已启用 Service 需要的项，每项显示通过、警告、失败或跳过，未通过的项附一条修复命令。
- 检查内容：Node 与 dsh 版本、本包是否在 Profile 的 bundle 中、配置修改能否即时生效；各 Service 的配置能否通过校验；钉钉的 dws 安装与登录态；Agent 任务的 provider 安装与权限声明；Jev 的 SDK 与 Key 来源（不输出 Key 本身）。
- `--json` 输出机器可读的报告；有失败项时退出码为 1，可以接入 CI。

## setup：交互式配置

<CopyCommand command="npx @mc/dsh-agent-kit setup --profile my-agent" />

1. 选择 Profile。没装本包时，会提示要执行的 `dsh plugin --profile <名字> add @mc/dsh-agent-kit`。
2. 多选要启用的 Service，已启用的默认勾选。
3. 逐个配置，当前值作为默认值：
   - 钉钉：选择身份；可以按群名搜索群，或直接输入群 ID；user 身份未登录时可以直接拉起 `dws auth login`；最后可以给自己发一条测试消息。
   - Agent 任务：工作目录；为 claude-code、codex 声明权限上限。
   - Jev：Key 输入时不回显；显示将保存到哪里；已有 Key 时可以保留。
4. 以差异视图展示 `cordis.patch.yml` 的改动，确认后才写入。密钥单独保存，不出现在差异中。
5. 自动运行 doctor。

任何一步取消都不会写入文件；已保存的密钥保留。

## 设置页：在 dsh Web 中操作

启动 Profile 后进入 dsh Web 的「设置 → Agent Kit」：

- 每个 Service 一张卡片：启用开关、运行状态、检查结果与配置表单。
- 保存时会比对配置文件的版本；如果期间有人改过这份文件（包括另一个终端里的 `setup` 或手动编辑），会提示冲突并刷新，避免覆盖。
- 保存成功后，dsh 会用新配置重新加载对应 Service，页面随后自动刷新状态。
- TypeSafe Key 只能写入或清除，不能读回；页面只显示「已配置」与来源。清除与 gitflow-cli 共用的钥匙串条目前会先确认。

<Figure src="/walkthrough/settings.png" alt="Agent Kit 设置页" caption="设置 → Agent Kit：启用开关、运行状态、检查结果与配置表单。" />

<Notice title="只读条件" tone="warn">
只有 dsh Web 绑定在 `127.0.0.1` 时设置页才可修改。绑定到其他地址，或没有加载 Web 服务时，设置页一律只读并显示原因。
</Notice>

## 密钥保存在哪里

| 平台 | setup 与设置页的默认保存位置 | 读取顺序 |
|---|---|---|
| macOS | 钥匙串，服务名 `ai.typesafe.api-key` | 环境变量 → 钥匙串 → dsh 凭据文件 |
| Linux | `$DSH_HOME/.credentials.yaml` | 环境变量 → dsh 凭据文件 |
| Windows | `$DSH_HOME/.credentials.yaml`，写入后收紧为仅当前用户可访问 | 环境变量 → dsh 凭据文件 |

dsh 凭据文件与 `.env` 一样是明文，只靠文件权限保护；Agent 子进程以同一用户运行，理论上可以读到它。
