## 接口

```ts
const r = await ctx.notify.send({
  text: '需要人工复核',
  targets: { dingtalk: { chatId: 'cid...' } },
  at: { dingtalk: { openDingtalkIds: ['...'] } },
  idempotencyKey: 'evt_...',
  traceId: 'evt_...',
  signal,
})
// r: { channel: 'dingtalk', results: Array<{ ok, messageId?, error? }> }
```

业务包只需 inject `notify`。启用 `agent-kit-notify` 与 `agent-kit-dingtalk` 两行，并把 notify 的 `channel` 设为 `dingtalk`。未启用钉钉或启动失败时，发送抛出 `channel_unavailable`；钉钉发送失败时保留 `DingtalkSendError` 的错误码与可重试标记。

`status()` 给出钉钉的运行与登录状态；`login()` / `logout()` 转给钉钉。`notify` 不 inject 钉钉 Service，而是在发送时查找它，因此停用钉钉不会卸载只依赖 `notify` 的业务插件。

<Notice title="钉钉行要单独启用" tone="warn">
`notify` 只负责转发，真正发送由已登录的 `dingtalk` Service 完成。`doctor` 会检查钉钉行是否启用。
</Notice>
